# assignment-wrapup: 과제 제출 정리 스킬

과제를 끝낼 때마다 반복하던 "README 정리"를 같은 원칙으로 해 주는 스킬입니다.

**원칙: 맨 위 README는 목록, 자세한 내용은 과제 폴더 README.**

## 불편 → 해결

| 불편 (매번 반복하던 일) | 해결 (이 스킬) |
|---|---|
| 과제를 끝낼 때마다 "README에 정리해 줘"라고 시키면, 회고와 진행 내용이 맨 위 README에 계속 쌓여 목록이 안 보이게 됨 (2026-11-02 기준 회고 4개가 맨 위에 몰려 있었음) | 맨 위 표에는 이름·요약·실행 URL·과제 URL 한 줄만, 진행 과정과 회고는 과제 폴더 README로 |
| 정리할 때마다 표 칸, 말투, 절 이름이 달라짐 | 표 모양과 "진행 과정 / 회고" 절 틀을 고정 |
| 회고를 AI가 쓰면 내가 겪지 않은 일까지 단정해서 쓰는 경우가 있었음 (todo 7-1 회고에서 확인하지 못한 로그인 실패를 "겪었다"고 써서 고침) | git 기록·문서·대화에서 확인된 사실만 쓰고, 추측이 섞일 수 있는 줄은 따로 확인받음 |
| 정리 뒤 링크 깨짐·파일 누락을 따로 점검해야 했음 | 마지막에 `submit-check` 스킬로 점검 |

## 언제 쓰나

- "과제 정리해 줘", "README에 제출 내용 정리", "회고 정리해 줘", "진행 과정 남겨 줘", "과제 목록에 추가해 줘"
- 과제 하나를 끝내고 GitHub에 올리기 전

## 파일

| 파일 | 내용 |
|---|---|
| `SKILL.md` | 이름·설명·절차 (재료 모으기 → 맨 위 표 한 줄 → 과제 README 진행 과정·회고 → 확인받고 마무리) |

## 이 스킬로 정리한 예

- 저장소 맨 위 [README.md](../../README.md): 과제 표 (1~7, 7-1)
- [todo/README.md](../../todo/README.md): "7-1 Subquest 진행 과정" 표와 "회고 (7-1 Subquest)"
