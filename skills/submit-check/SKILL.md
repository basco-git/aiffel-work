# 제출 전 점검

과제 폴더를 올리기 전에, 사람이 눈으로 놓치기 쉬운 다섯 가지를 스크립트로 같은 기준으로 확인한다.
판단은 스크립트 결과로 하고, 고치는 것은 사용자 확인을 받은 뒤에 한다.

## 1. 대상 정하기

- 사용자가 폴더를 말하면 그 폴더, 말하지 않으면 지금 작업 중인 과제 폴더를 대상으로 한다.
- 대상이 애매하면(저장소 맨 위에서 실행했는데 과제가 여러 개) 어느 과제인지 묻는다.
- 기준 브랜치는 `origin/main`이다. 먼저 `git fetch -q origin`으로 최신 상태를 받는다.

## 2. 스크립트 실행

이 스킬 폴더의 `scripts/submit_check.py`를 git 저장소 안에서 실행한다. 표준 라이브러리만 쓰므로 아무 Python 3.9 이상이면 된다.

```bash
python -I "<이 스킬 폴더>/scripts/submit_check.py" <과제 폴더> --base origin/main
```

- Windows에서 `python`이 없으면 과제 폴더의 `.venv/Scripts/python.exe`나 `py -3`를 쓴다.
- 종료 코드 0은 문제 없음(확인 필요 항목은 있을 수 있음), 1은 문제 있음.

| 번호 | 점검 | 문제로 보는 경우 |
|---|---|---|
| 1 | 링크·이미지가 git에 있음 | `.md`의 상대 경로 링크·이미지가 없는 파일이거나, 파일은 있는데 `.gitignore` 때문에 git에 없음, 또는 링크의 `#앵커`가 대상 문서 제목에 없음(맨 위 README에서 과제 폴더로 가는 링크 포함) |
| 2 | 비밀값 없음 | 올라갈 파일에 키·토큰·비밀번호 형태의 값, 또는 `.env` 파일 자체가 있음 (값은 출력하지 않음) |
| 3 | 이미지 메타데이터 | 올라갈 이미지에 위치 정보(GPS)가 있음. EXIF·텍스트 태그만 있으면 "확인 필요" |
| 4 | 맨 위 README 목록 | 저장소 맨 위 `README.md`에 과제 폴더 링크가 없음 |
| 5 | 커밋·푸시 상태 | 커밋 안 한 변경, `origin/main`에 아직 없는 커밋 ("확인 필요"로만 표시) |

## 3. 결과 보고

스크립트 출력을 그대로 붙이지 말고, 아래 모양의 표로 한국어로 정리한다.

| 점검 | 결과 | 할 일 |
|---|---|---|
| 1. 링크·이미지 | 통과 / 확인 필요 / 문제 | 문제면 무엇을 어떻게 고칠지 한 줄 |

- 문제 항목마다 원인과 고치는 방법을 적는다. 예: `.gitignore`가 `.claude/`를 통째로 빼서 스킬 파일이 없음 → `skills/`만 예외로 허용.
- "확인 필요" 이미지는 직접 열어 보고, 사람 얼굴·이메일·주소·전화번호가 보이는지 함께 적는다.
- 스크립트가 보지 못하는 것은 "직접 확인할 것"으로 따로 적는다: 캡처 속 개인정보, 배포 주소가 실제로 열리는지, 제출 양식에 적을 URL.

## 4. 고치기

- 고칠 목록을 보여 주고 확인받은 뒤 고친다. 비밀값이 나온 경우에는 값을 출력하지 말고, 이미 커밋된 값이면 키를 새로 발급해야 한다고 알린다.
- 고친 뒤 스크립트를 다시 실행해 모두 통과한 결과로 마무리한다.
- 커밋·푸시·PR 병합은 사용자가 요청할 때만 한다.

## 하지 말 것

- 비밀값으로 의심되는 문자열을 화면, 파일, 커밋 메시지에 옮겨 적지 않는다.
- 점검을 통과시키려고 링크를 지우거나 `.gitignore`를 통째로 풀지 않는다. 필요한 경로만 예외로 연다.
- 스크립트 결과 없이 "문제 없음"이라고 말하지 않는다.
