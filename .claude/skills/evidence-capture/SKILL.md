# 확인 장면 캡처

캡처는 "실제로 이렇게 됐다"는 증빙이다. 그래서 **실제로 실행한 결과만** 그리고, 다시 그린 화면이라는 사실을 문서에 밝힌다.

## 1. 장면 정하기

- 무엇을 증명하는 장면인지 한 줄로 정한다. 예: "MCP가 허용 폴더 3개만 열고 todo 폴더는 막는다".
- 증빙은 **결과가 보이는 화면**이어야 한다. 확인 창만 찍고 결과를 빠뜨리지 않는다(예: 삭제 확인창 + 삭제 뒤 목록).
- 번호는 문서의 기존 표를 이어서 붙인다(`C4` 다음은 `C5`). 파일 이름은 `<번호>-<영문 짧은 설명>.png`.

## 2. 실제로 실행해 결과 얻기

- 장면에 넣을 명령이나 도구를 **이번 대화에서 실제로 실행**하고 출력을 받는다. 기억이나 예상으로 출력을 지어내지 않는다.
- 실행할 수 없는 장면(예: Claude Code의 `/mcp` 화면처럼 이 대화에서 볼 수 없는 화면)은 그리지 말고, 사용자에게 `Win+Shift+S`로 직접 찍어 달라고 요청한다.
- 출력에 이메일, 비밀번호, 토큰, 키, 전화번호가 있으면 앞부분만 남기고 가린다(`ab***@gmail.com`). `.env` 내용은 넣지 않는다.

## 3. HTML로 그리기

- 이 스킬 폴더의 `assets/template.html`과 `assets/base.css`를 작업 폴더(scratchpad 등 저장소 밖)에 복사해 쓴다. HTML 원본은 저장소에 올리지 않는다.
- 창 제목 줄(`.title`)에 프로그램과 장면 이름을 쓴다. 예: `Claude Code — todo (MCP 서버 todo-files 연결 확인)`.
- 출력은 실제 결과를 그대로 옮긴다. 너무 길면 `...`로 줄이되 증명할 부분은 남긴다.
- 색: 명령 `.cmd`, 성공·파일 이름 `.g`, 키 이름 `.c`, 강조 값 `.y`, 흐린 설명 `.dim`, 오류는 `style="color:#e74856"`.

## 4. PNG로 만들기

```bash
python -I "<이 스킬 폴더>/scripts/render.py" <장면.html> <과제 폴더>/docs/screenshots/<번호>-<이름>.png
```

- 높이는 스크립트가 자동으로 잰다. 폭은 기본 960, 긴 줄이 있으면 `--width 1100`.
- Chrome이나 Edge가 필요하다. 못 찾으면 `CHROME_PATH` 환경 변수로 경로를 알려 준다.
- **만든 이미지를 직접 열어 본다.** 잘림, 줄바꿈 깨짐, 한글 깨짐, 가리지 않은 개인정보가 없는지 확인하고, 문제가 있으면 고쳐서 다시 만든다.

## 5. 문서에 넣기

- 제출 문서(보통 `SUBMISSION.md`)의 확인 장면 표에 한 줄을 추가한다.

  `| C5 | 확인한 것 | 결과 (날짜, 숫자, 실제 문구) | ![C5](docs/screenshots/C5-이름.png) |`

- 표 위의 안내 문장에 다시 그린 장면 번호를 넣는다. 예: `C3·C4·C5는 실제 실행 결과를 HTML로 다시 그린 화면이다(문구·값은 실행 결과 그대로).`
- 저장소 맨 위 README에 캡처 표가 있으면 같은 줄을 링크로 추가한다.
- 끝나면 만든 파일 경로와 추가한 줄을 보고한다. 커밋은 사용자가 요청할 때 한다.

## 하지 말 것

- 실행하지 않은 결과, 바꾼 숫자, 성공으로 꾸민 오류를 그리지 않는다.
- 다시 그린 화면을 실제 캡처처럼 소개하지 않는다.
- 실제 서비스나 다른 사람의 화면을 흉내 내지 않는다. 내 터미널과 내 Claude Code 대화만 그린다.
