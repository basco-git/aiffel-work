## 1. 한 줄 요약

재직자 이탈 예측 점수를 **면담 예산이라는 업무 결정**으로 바꿔 보여 주는 도구. 두 단계로 묻는다.

- **1단계 (교안 17번 그대로):** "위험 점수 상위 몇 %까지 면담하면 비용 대비 이득인가?" — 기준선과 모델을 같은 시험 자료로 비교하고, 정확도·AUC·문턱의 차이를 체험한다.
- **2단계 (교안 확장 + 현업 반영):** "**누구를, 누가(팀장 / 임원) 면담해야** 하는가?" — 퇴사 사유와 면담자 권한의 궁합에 따라 효과가 다르다는 현업 경험을 반영해, 한정된 임원 면담 슬롯과 팀장 면담을 배분한다. 위험 순(1단계 결과)을 기준선으로 두고 업리프트 모델과 비교한다.

핵심 가치는 모델 개발이 아니라 **점수 → 문턱 → 비용 결정을 연결하는 방법**, 그리고 **"무엇을 예측해야 하는가"를 질문하는 습관**이다. 도구는 **대기 순서**를 정하고, 실제 사유 확인과 판단은 **면담하는 사람**이 한다.

## 2. 배경과 문제

- 인사팀은 퇴사 징후가 있는 직원에게 면담·처우 조정을 하고 싶지만 시간과 예산이 한정돼 **누구부터** 할지 정해야 한다.
- 예측 모델이 있어도 "AUC 0.8"만으로는 몇 명을 면담해야 하고 얼마나 이득인지 알 수 없다.
- **떠날 위험이 높은 사람이 면담 효과도 큰 사람이라는 보장이 없다.** 이미 마음을 굳힌 사람에게는 면담이 소용없고, 원래 남을 사람에게는 면담이 낭비다.
- **현업 경험(INTERVIEW Q9):**
  - 면담 효과는 사람마다 다르고 크기도 다르다.
  - 면담자 직위가 높을수록(팀장 < 실장 < 본부장 < 대표) 효과가 크다.
  - 주요 퇴사 사유는 ① 연봉 수준 ② 원하는 업무 여부 ③ 급여 외 복지·보상 ④ 팀장 등 주변인 갈등 ⑤ 회사의 방향성·성장이다.
  - 직위가 높을수록 효과가 큰 이유는 **사유를 해결할 권한**(처우 조정, 부서 이동, 비전 공유)이 있기 때문으로 해석한다. 팀장 갈등이 사유라면 팀장 면담은 역효과일 수 있다.
- 임원의 시간은 비싸고 적다. 실무 질문은 "**한정된 임원 면담 슬롯을 누구에게 줄까**"이다.

## 3. 사용자와 시나리오

**주 사용자:** 인사팀 담당자(HRBP). 모델·통계 지식은 많지 않다.

1. 페이지를 연다. 첫 화면에 "가상 데이터로 만든 시뮬레이션", "지원 대상 선정용, 개인 평가 금지"가 보인다.
2. 퇴사 1건당 대체 비용, 팀장 면담 비용, 임원 면담 비용, (1단계) 면담 성공률을 입력한다.
3. **1단계:** 슬라이더로 "상위 k%까지 면담"을 정하고, 찾은 퇴사 위험자 수·불필요한 면담 수·예상 순이익을 기준선(무작위, 근속 짧은 순)과 비교한다.
4. **2단계:** 임원 면담 슬롯 수(`m`)와 팀장 면담 비율(`k`)을 정한다. 시나리오(효과 균일 / 사유×직위 궁합)를 바꿔 가며 위험 순 배분과 효과 순 배분의 순이익을 비교한다.
5. 결과 요약 문장을 복사해 보고 자료에 붙인다.

## 4. 목표 / 비목표

**목표**
- G1. 같은 시험 자료로 기준선과 모델을 공정하게 비교한 결과를 보여 준다.
- G2. 문턱(면담 대상 비율, 임원 슬롯 수)을 바꾸면 결과가 어떻게 달라지는지 즉시 체험하게 한다.
- G3. 정확도와 AUC의 차이, 점수와 업무 결정의 거리를 화면에서 설명한다.
- G4. 개인 평가가 아닌 **지원 대상 선정**용 도구임을 설계로 보장한다.
- G5. **가상 데이터의 한계를 숨기지 않는다.** (§5.6)
- G6. 위험 예측과 효과 예측(업리프트)의 차이를 시나리오 2종으로 보여 주고, **효과가 균일하면 단순한 방법으로 충분하다**는 결론도 그대로 보여 준다.
- G7. 분석 과정과 결과를 보고서(`docs/REPORT.md`)로 남긴다. 수치는 결과 JSON에서만 옮긴다.
- G8. 현업 지식(사유 × 면담자 권한)을 생성 규칙에 명시적으로 담고, **어떤 조건에서 업리프트가 위험 순을 이기는지**를 민감도 분석(P1)으로 보여 준다.

**비목표**
- 실제 직원 데이터 처리(업로드 포함), 개인 이름·식별 정보 표시.
- 채용(합격 예측). 편향·차별 이슈가 커서 제외.
- 원인 분석. 요인은 상관관계로만 안내.
- 서버, 로그인, DB.
- 생존 분석(퇴사 시점 예측) — 제외 (INTERVIEW Q3)
- 면담의 질(정석대로 했는가) 모델링 — 데이터화가 어려워 보고서 한계로만 기록 (INTERVIEW Q9)
- 실장·본부장·대표의 세분 — 처치를 **팀장 / 임원** 2종으로 단순화

### 5.2 규모와 설계

- 규모: 기본 **9,000명** (옵션 `--n`), 시드 기본값 `42`.

### 5.4 생성 규칙 ① 면담하지 않았을 때의 퇴사 위험

`logit0 = b0 + Σ(계수 × 표준화한 열) + 잡음`, 잡음 ~ N(0, σ), 초기값 σ = 1.0

| 요인 | 초기 계수(표준화 기준) | 의도 |
|---|---|---|
| `leader_conflict` (0/1, 원척도) | +0.9 | 갈등 있음 → 위험 ↑ (강) |
| `sat_pay` | −0.6 | 사유 ① (강) |
| `sat_job_fit` | −0.6 | 사유 ② (강) |
| `sat_direction` | −0.5 | 사유 ⑤ (중) |
| `overtime_hours_month` | +0.5 | 야근 (중) |
| `sat_benefits` | −0.3 | 사유 ③ (약~중) |
| `years_since_promotion` | +0.3 | 승진 정체 (약~중) |
| `monthly_income_rank` | −0.3 | 급여 상대 수준 (약~중) |
| `tenure_years < 1` (지시 변수) | +0.4 | 신입 |
| `commute_minutes` | +0.2 | 통근 (약) |
| `training_hours_year` | −0.2 | 교육 (약) |
| `age` | −0.25 | 젊을수록 위험 ↑ (약). **민감 열이 결과에 스며드는 것을 공정성 점검에서 보여 주려는 의도적 설계** |
| `gender`, `marital_status` | 0 | 영향 없음 |
| `b0` | 조정 | **대조군 퇴사 비율이 약 15%** 가 되도록 구현 때 맞춘다(목표값, 측정값 아님) |

### 5.5 생성 규칙 ② 면담 효과 (로짓에서 빼는 양)

면담한 사람: `logit = logit0 − δ`, `left ~ Bernoulli(sigmoid(logit))`. 안 한 사람: `sigmoid(logit0)`.
`δ_lead`(팀장 면담 효과)와 `δ_exec`(임원 면담 효과)를 사람마다 계산한다. 아래에서 `low_x = (5 − sat_x) / 4` (불만 정도 0~1).

**이미 마음을 굳힌 사람 (숨은 변수, 관측 안 됨):** `decided ~ Bernoulli(0.5 × sigmoid(logit0))`. `decided = 1`이면 시나리오 B에서 두 면담 효과 모두 0이다. "사람마다 다른 특성을 통계로 다 잡을 수 없다"(Q9)를 데이터에 반영한 장치다. 모델은 이 열을 볼 수 없다.

| 시나리오 | `δ_lead` (팀장) | `δ_exec` (임원) | 의미 |
|---|---|---|---|
| **A (효과 균일)** | 모두 0.4 | 모두 0.8 | 임원이 언제나 2배 효과. 위험 순 배분이 거의 최선일 것으로 예상 |
| **B (사유 × 권한 궁합)** | `0.3 + 0.3·low_job_fit + 0.1·low_direction − 0.8·leader_conflict` (−0.4 하한) | `0.2 + 0.6·low_pay + 0.5·low_job_fit + 0.2·low_benefits + 0.7·leader_conflict + 0.6·low_direction` | 아래 표 |

- 시나리오 B의 두 효과는 `decided`를 반영한 뒤 **평균이 각각 0.4, 0.8이 되도록 배율 조정**해 A와 평균을 같게 맞춘다. 차이가 "효과의 분포"에서만 오게 하기 위해서다.
- 시나리오 B의 설계 근거 (INTERVIEW Q9):

| 퇴사 사유 | 팀장 면담 | 임원 면담 |
|---|---|---|
| ① 연봉 불만 | 권한 없음 → 효과 없음 | 처우 조정 권한 → 큼 |
| ② 원하는 업무 아님 | 팀 안 조정 → 작음 | 부서 이동 권한 → 큼 |
| ③ 복지·보상 불만 | 효과 없음 | 일부(제도는 개인 면담으로 한계) |
| ④ 팀장 등 갈등 | **역효과** | 큼 |
| ⑤ 회사 방향·성장 | 약함 | 비전 공유 → 큼 |

**진짜 값 (검증 전용 `data/truth_<A|B>.csv`, 모델 입력에 쓰지 않음):** `emp_id`, `decided`, `p_none = sigmoid(logit0)`, `p_lead`, `p_exec`, `tau_lead = p_none − p_lead`, `tau_exec = p_none − p_exec`.

### 5.6 가상 데이터의 한계 (화면과 README·보고서에 반드시 표기)

- 퇴사 규칙과 면담 효과를 우리가 직접 정했으므로, **모델이 잘 맞추는 것은 규칙을 다시 찾은 것**이다. 실제 회사 성능을 뜻하지 않는다.
- **시나리오 B의 사유 × 권한 궁합은 HR 현업 경험(1인)에 바탕을 둔 가정**이다. 실제 조직에서 같은 구조인지는 검증되지 않았다. 그래서 효과가 균일한 시나리오 A와 민감도 분석(P1)을 함께 보여 준다.
- **시나리오 B에서 업리프트가 이기는 것은 그렇게 설계했기 때문**이다.
- 면담의 질(정석대로 했는가)과 실장·본부장·대표의 차이는 모델에 없다.
- 이 프로젝트가 보여 주는 것은 "예측 성능"이 아니라 **"점수 → 문턱 → 비용 결정"을 연결하는 방법과 "무엇을, 누구의 개입으로" 정하는 판단**이다.
- 진짜 개인별 효과(`truth`)는 실제 자료에서는 알 수 없다. 이 값을 쓰는 비교는 "가상 데이터라 가능한 검증"으로 표시한다.
- **실무 적용 조건:** 무작위 시범 면담 기록(대조·팀장·임원)으로 같은 절차를 다시 돌려야 한다(보고서 "실제 도입 검증 절차" 절).

## 6. 모델링과 평가

### 6.1 분할

- 전체 행에서 시험 자료 **30%** 를 한 번 떼어 끝까지 고정한다. 층화 기준은 `talk_by × left`, 시드 고정.
- 1단계는 훈련·시험 각각의 **대조군(`talk_by = none`)만** 쓴다 → "면담하지 않았을 때의 위험"을 배운다.
- 2단계는 훈련·시험의 **전체 행**을 쓴다.
- 시험 정답은 채점에만 쓴다. 모델 선택·보정은 **훈련 자료 안의 교차 검증(5겹)** 으로 한다.

### 6.2 1단계: 위험 예측 (교안 17번 그대로)

| 구분 | 방법 | 역할 | 우선순위 |
|---|---|---|---|
| 기준선 1 | 무작위 순서 (시드 고정) | 아무것도 모를 때 | P0 |
| 기준선 2 | 근속 연수 짧은 순 | 사람이 쓰는 단순 규칙 | P0 |
| 기준선 3 | 로지스틱 회귀 | 단순 모델 | P0 |
| 모델 | 랜덤 포레스트 | 표 데이터 기본 모델 (교안) | P0 |
| 모델 | HistGradientBoosting | sklearn 내장 빠른 부스팅 | P0 |
| 모델 | GradientBoostingClassifier | 교안의 그래디언트 부스팅 | P1 |
| 제외 | TabICL·TabPFN·LightGBM | 일정상 제외 | — |

- 입력 열: §5.3의 "모델 입력 O" 열. 하이퍼파라미터는 기본값(시험 점수로 튜닝하지 않음).
- **확률 보정 (P0):** `CalibratedClassifierCV`(훈련 자료 5겹, isotonic). 보정 전후 Brier 점수와 신뢰도 곡선(10구간)을 저장한다.
- **1단계 대표 모델:** 훈련 자료 교차 검증 AUC가 가장 높은 모델. 2단계의 "위험 순" 기준선으로 넘긴다.

### 6.3 2단계: 누구를 누가 면담할까 (업리프트, 교안 확장)

**효과 추정 (P0):** 후보 3종 — T-learner(HistGB), T-learner(로지스틱), S-learner(로지스틱 + 처치 상호작용) — 중 **훈련 자료 5겹 교차 검증의 관측 Qini(팀장·임원 평균)** 가 가장 큰 것을 고른다(v0.5, 근거: ANALYSIS_LOG 21:19). `τ̂_lead = p̂_none − p̂_lead`, `τ̂_exec = p̂_none − p̂_exec`.

**배분 규칙 (웹에서 계산, 모든 방법에 같은 규칙):** 입력은 임원 슬롯 수 `m`, 팀장 면담 수 `L = round(N × k)`.
1. 사람마다 가치 계산: `V_exec = τ × C_replace − C_exec`, `V_lead = τ × C_replace − C_lead` (τ는 방법마다 다름)
2. 임원 슬롯: `V_exec − max(V_lead, 0)`(팀장 대신 임원을 쓸 때 더 얻는 이익)이 큰 순서로 `m`명
3. 팀장 면담: 남은 사람 중 `V_lead`가 큰 순서로 `L`명
4. 동점은 Python이 저장한 `tiebreak`(고정 시드 무작위 순번)로 깬다

| 방법 | 쓰는 τ | 역할 | 우선순위 |
|---|---|---|---|
| 무작위 | 없음 (`tiebreak` 순서로 임원 m명, 다음 L명 팀장) | 아무것도 모를 때 | P0 |
| **위험 순** | 1단계 보정 확률 `p̂`를 τ 대신 사용 (위험 높은 순으로 임원, 다음 팀장) | 교안 방식 그대로 쓰면 | P0 |
| **효과 순** | `τ̂_lead`, `τ̂_exec` (T-learner) | 업리프트 | P0 |
| 상한 | `tau_lead`, `tau_exec` (`truth`) | 가상 데이터라서만 가능한 최선 | P0 |
| 기준선 | **HR 전문가 규칙**: 권한 필요자(팀장 갈등 또는 연봉·원하는 업무·회사 방향 만족 ≤ 2)를 위험 순으로 임원 m명, 남은 사람 중 팀장 갈등이 없는 사람을 위험 순으로 팀장 L명 | 모델 없이 현업 지식만 (v0.5, Q10). 시나리오 B와 같은 경험에서 나왔으므로 B에서의 우위는 자기 가정과 맞춘 비교 | P0 |

- 시나리오 A·B 각각 같은 절차로 실행한다.

### 6.4 지표

| 지표 | 단계 | 뜻 |
|---|---|---|
| 정확도 (문턱 0.5) | 1 | 전체 시험 행 중 맞힌 비율 |
| 전원 재직 정확도 | 1 | "모두 남는다"고만 답할 때의 정확도. 정확도 함정을 보이는 기준 |
| ROC AUC | 1 | 퇴사자에게 재직자보다 높은 점수를 주는 정도 |
| Brier 점수 (보정 전/후) | 1 | 확률이 실제와 얼마나 가까운지 (낮을수록 좋음) |
| 포착률@k | 1 | 전체 퇴사자 중 상위 k%에 들어온 비율 (k = 5, 10, 20, 30%) |
| 리프트@k | 1 | 상위 k%의 퇴사자 비율 ÷ 전체 퇴사자 비율 |
| Qini 계수 (팀장·임원 각각) | 2 | 효과 순으로 줄 세운 정도. 해당 면담군과 대조군의 관측 결과로 계산. 무작위 = 0 |
| 진짜 효과 상관 (팀장·임원 각각) | 2 | `τ̂`와 진짜 `tau`의 스피어만 순위 상관. **가상 데이터라 가능한 검증** |
| 순이익 | 1·2 | §7 식, 웹에서 계산 |

### 6.5 설명·공정성 (P1)

- **순열 중요도:** 1단계 대표 모델과 T-learner의 `τ̂_exec`에 대해 시험 자료에서 계산한다(보고용, 모델 선택에 쓰지 않음). "원인이 아니라 상관"으로 안내한다. 사유 5종이 위험과 효과에서 각각 어떻게 다르게 나타나는지 보여 주는 것이 목적이다.
- **집단별 점검:** 나이대(30세 미만 / 30대 / 40대 / 50세 이상)·성별마다 기본 입력(§7 예시값)에서의 임원 배정 비율, 팀장 배정 비율, 포착률을 위험 순과 효과 순 각각으로 계산한다.
- 민감 열 포함 모델 재학습(F8 전체판)은 제외한다.

### 6.6 민감도 분석 (P1) — v0.5에서 축 변경 (Q10)

- 질문: "**시범 면담을 몇 명 하면 효과 추정이 위험 순을 넘는가?**" (첫 결과에서 9,000명으로는 넘지 못함)
- 시나리오 B 생성식에서 **시범 인원 n ∈ {9,000, 30,000, 90,000, 300,000}** × **궁합 강도 s ∈ {0, 0.5, 1.0}** (s = 0은 균일 효과), 조건마다 시드 3개. 300,000은 30,000에서도 넘지 못해 교차점을 찾으려고 추가(21:30).
- 위험 모델(로지스틱 보정)과 효과 추정기(T-HistGB)는 본 실행 선택으로 고정. 배분 입력은 예시값.
- 조건마다 효과 순·전문가 규칙·상한의 순이익과 위험 순 대비 비율, 진짜 효과 상관을 `results/sensitivity.json`에 저장하고, 보고서에 조건표로 싣는다.
- 이전 계획(잡음 σ × 궁합 강도)은 위 질문보다 실무 가치가 낮아 바꿨다.

### 6.7 원칙

- 직접 실행한 값만 기록한다. 17번 원문 수치나 추정치로 채우지 않는다.
- 분할 시드, 패키지 버전, 실행 시간, 갈래별 실제 퇴사 비율, `decided` 비율, 최종 생성 계수를 `results/meta.json`에 남긴다.
- 순위·동점 처리는 Python에서 고정해 저장하고, 웹은 저장된 `tiebreak`만 쓴다.

## 7. 비용 계산 (웹에서 계산)

**입력**

| 입력 | 뜻 | 예시값(버튼) |
|---|---|---|
| `C_replace` | 퇴사 1건당 대체 비용 | 3,000만 원 |
| `C_lead` | 팀장 면담 1건 비용 (1단계의 면담 비용으로도 사용) | 30만 원 |
| `C_exec` | 임원 면담 1건 비용 | 150만 원 |
| `r` | (1단계만) 면담한 퇴사 위험자 중 퇴사를 막는 비율 | 0.3 |
| `k` | 1단계: 면담 대상 비율 / 2단계: 팀장 면담 비율 | 20% |
| `m` | (2단계) 임원 면담 슬롯 수 | 시험 인원의 5% |

- 기본값 없이 시작하고, "예시값 채우기" 버튼은 **예시임을 화면에 표시**한다.

**1단계 (단순 가정: 한 종류 면담, 성공률 `r`이 모두 같음)** — 시험 대조군 N명

- `S = round(N × k)`, `TP` = 선정된 실제 퇴사자 수
- 불필요한 면담 = `S − TP`
- 예상 순이익 = `TP × r × C_replace − S × C_lead`
- **기대이익 문턱 비교:** 보정 확률 `pᵢ`로 `pᵢ × r × C_replace > C_lead`인 사람만 고르는 방식의 순이익과 인원을 같은 화면에 표시한다.

**2단계 (사람마다, 면담자마다 효과가 다름)** — 시험 전체 행, §6.3 배분 규칙

- 예상 순이익 = `Σ(임원 배정자의 tau_exec) × C_replace + Σ(팀장 배정자의 tau_lead) × C_replace − m × C_exec − L × C_lead`
- 진짜 효과(`truth`)로 채점한다. "가상 데이터라서 알 수 있는 값"이라고 표시한다.
- 팀장 갈등 사유가 있는 사람에게 팀장 면담이 배정되면(효과가 음수일 수 있음) 그 인원을 별도로 표시한다.

문구: "가정에 따른 시뮬레이션이며 실제 이득을 보장하지 않습니다."

## 11. 윤리·보안 요구사항

- 점수는 면담·지원 대상 선정용이며 평가·징계·해고 근거로 쓰지 않는다고 화면·README·보고서에 명시한다.
- 개인 이름·ID를 표시하지 않는다. `scores.json`에는 행 번호만 둔다.
- 민감 열은 모델 입력에서 제외한다. 공정성 점검에서만 집계로 쓴다.
- 요인 설명은 상관으로 한정한다.
- 업리프트로 "효과가 작은 사람"을 고르는 것은 **지원을 끊는 근거가 아니라 한정된 예산·임원 시간의 우선순위**임을 명시한다. 임원 면담 배정이 "중요한 직원" 표시로 오해되지 않게 한다.
- **사유 데이터의 출처 (INTERVIEW Q9):** 사유 5종은 조직문화 진단(설문) 문항을 가정한다. **익명을 약속한 설문을 개인 단위 선정에 쓰면 신뢰가 깨진다.** 실제 적용 시 기명 수집 여부와 동의를 먼저 확인해야 하며, 팀장 갈등 문항은 기명이면 축소 보고되기 쉽다. 실무에서는 사유를 면담(stay interview)에서 확인하는 용도가 더 적합할 수 있다. 화면 고지와 보고서에 넣는다.
- 가상 데이터임과 그 한계(§5.6)를 첫 화면에 표시한다.
- 실제 직원 자료는 사내 규정 확인 없이 사용하지 않는다(17번 6파트).

## 16. 용어

| 용어 | 뜻 |
|---|---|
| 양성 | 찾아내려는 쪽. 여기서는 퇴사 |
| 기준선 | 새 방법의 이점을 판단하려고 함께 비교하는 기존 방법 |
| AUC | 퇴사자에게 재직자보다 높은 점수를 주는 정도(점수 순서의 구별 능력). 전체 행의 몇 %를 맞혔다는 뜻이 아님 |
| 문턱(`k`, `m`) | 몇 명까지 면담 대상으로 볼지 정하는 기준 |
| 포착률 | 전체 퇴사자 중 선정된 대상에 들어온 비율 |
| 리프트 | 선정 대상의 퇴사자 비율이 전체 평균의 몇 배인지 |
| 확률 보정 | 점수가 실제 확률과 맞도록 고치는 일 |
| Brier 점수 | 예측 확률과 실제 결과(0/1)의 차이 제곱 평균. 낮을수록 좋음 |
| 업리프트 | 면담했을 때와 안 했을 때의 퇴사 확률 차이. "면담 효과" |
| T-learner | 처치 갈래마다 모델을 따로 학습해 예측의 차이로 효과를 추정하는 방법 |
| Qini 곡선·계수 | 효과 순으로 줄 세웠을 때 누적으로 막은 퇴사 수를 그린 곡선과 그 면적 요약. 무작위 = 0 |
| 대조군 / 면담군 | 시범 운영에서 면담하지 않은 사람 / 면담한 사람 (무작위 배정) |
| 사유 × 권한 궁합 | 퇴사 사유를 해결할 권한이 면담자에게 있을 때 면담 효과가 커진다는 가정 (시나리오 B) |
| `decided` | 이미 마음을 굳혀 어떤 면담에도 반응하지 않는 사람. 관측되지 않는 숨은 변수 |
| 민감도 분석 | 가정(잡음, 궁합 강도)을 바꿔 가며 결론이 유지되는지 확인하는 일 |
