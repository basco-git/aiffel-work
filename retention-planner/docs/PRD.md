## 1. 한 줄 요약

재직자 이탈 예측 점수를 **면담 예산이라는 업무 결정**으로 바꿔 보여 주는 도구. 두 단계로 묻는다.

- **1단계 (교안 17번 그대로):** "위험 점수 상위 몇 %까지 면담하면 비용 대비 이득인가?" — 기준선과 모델을 같은 시험 자료로 비교하고, 정확도·AUC·문턱의 차이를 체험한다.
- **2단계 (교안 확장):** "떠날 사람이 아니라 **면담하면 남을 사람**을 고르면 더 나은가?" — 위험 순(1단계 결과)을 기준선으로 두고 업리프트 모델과 비교한다.

핵심 가치는 모델 개발이 아니라 **점수 → 문턱 → 비용 결정을 연결하는 방법**, 그리고 **"무엇을 예측해야 하는가"를 질문하는 습관**이다.

## 2. 배경과 문제

- 인사팀은 퇴사 징후가 있는 직원에게 면담·처우 조정을 하고 싶지만 시간과 예산이 한정돼 **누구부터** 할지 정해야 한다.
- 지금은 감이나 근속 연수 같은 단순 기준에 의존하기 쉽다.
- 예측 모델이 있어도 "AUC 0.8"만으로는 몇 명을 면담해야 하고 얼마나 이득인지 알 수 없다.
- 더 근본적으로, **떠날 위험이 높은 사람이 면담 효과도 큰 사람이라는 보장이 없다.** 이미 마음을 굳힌 사람에게는 면담이 소용없고, 원래 남을 사람에게는 면담이 낭비다.

## 3. 사용자와 시나리오

**주 사용자:** 인사팀 담당자(HRBP). 모델·통계 지식은 많지 않다.

1. 페이지를 연다. 첫 화면에 "가상 데이터로 만든 시뮬레이션", "지원 대상 선정용, 개인 평가 금지"가 보인다.
2. 퇴사 1건당 대체 비용, 면담 1건당 비용, (1단계) 면담 성공률을 입력한다.
3. 슬라이더로 "상위 k%까지 면담"을 정한다.
4. **1단계:** 찾은 퇴사 위험자 수, 불필요한 면담 수, 예상 순이익을 기준선(무작위, 근속 짧은 순)과 비교한다.
5. **2단계:** 시나리오(효과 균일 / 사람마다 다름)를 바꿔 가며 위험 순과 효과 순의 순이익을 비교한다.
6. 결과 요약 문장을 복사해 보고 자료에 붙인다.

## 5. 데이터 (가상 데이터 직접 생성)

### 5.1 원칙

- `ml/generate_data.py`가 **시드를 고정해 재현 가능하게** 생성한다. 같은 시드면 같은 파일이 나와야 한다.
- 실제 사람·회사 자료를 쓰지 않는다. 모든 값은 생성 규칙에서 나온다.
- 생성 규칙을 코드 상단 표와 이 문서에 함께 남긴다. 구현 중 조정한 최종 값은 코드 상단 표와 `results/meta.json`에 기록한다.
- **시나리오 A와 B는 같은 직원·같은 무작위 추첨을 쓰고 면담 효과 규칙만 다르다.** 차이가 시나리오 때문임을 보장하기 위해서다.

### 5.2 규모와 설계

- 규모: 기본 **6,000명** (옵션 `--n`), 시드 기본값 `42`.
  - v0.2의 3,000명에서 늘린 이유: 1단계는 면담하지 않은 절반(대조군)만 쓰므로, 시험 자료의 퇴사자가 너무 적어지지 않게 하기 위해서다(시험 30% × 대조군 50% × 퇴사 약 15% ≈ 135명).
- **시범 면담:** 전체의 **50%를 무작위로 면담**한 기록으로 가정한다(`treated`). 실제 도입 절차의 "작게 시작해 비교하기"(17번 6파트)에 해당한다.

### 5.4 생성 규칙

**① 면담하지 않았을 때의 퇴사 위험 (로지스틱)**

`logit0 = b0 + Σ(계수 × 표준화한 열) + 잡음`, 잡음 ~ N(0, σ), 초기값 σ = 1.0

| 요인 | 초기 계수(표준화 기준) | 의도 |
|---|---|---|
| `satisfaction` | −0.9 | 만족도 낮음 → 위험 ↑ (강) |
| `overtime_hours_month` | +0.8 | 야근 많음 → 위험 ↑ (강) |
| `years_since_promotion` | +0.5 | 승진 정체 → 위험 ↑ (중) |
| `monthly_income_rank` | −0.5 | 급여 상대 수준 낮음 → 위험 ↑ (중) |
| `tenure_years < 1` (지시 변수) | +0.5 | 신입 → 위험 ↑ (약~중) |
| `commute_minutes` | +0.2 | 통근 길음 → 위험 ↑ (약) |
| `training_hours_year` | −0.2 | 교육 많음 → 위험 ↓ (약) |
| `age` | −0.25 | 젊을수록 위험 ↑ (약). **민감 열이 결과에 스며드는 것을 공정성 점검에서 보여 주려는 의도적 설계** |
| `gender`, `marital_status` | 0 | 영향 없음 |
| `b0` | 조정 | **대조군 퇴사 비율이 약 15%** 가 되도록 구현 때 맞춘다(목표값, 측정값 아님) |

**② 면담 효과 (로짓에서 빼는 양 δᵢ)**

`logit1 = logit0 − δᵢ`, 면담한 사람은 `left ~ Bernoulli(sigmoid(logit1))`, 안 한 사람은 `sigmoid(logit0)`

| 시나리오 | δᵢ | 의미 |
|---|---|---|
| **A (효과 균일)** | 모두 0.7 | 면담 효과가 누구에게나 같음. 위험 순 선정이 거의 최선일 것으로 예상 |
| **B (효과가 사람마다 다름)** | `raw = 0.7 + 0.6·z(years_since_promotion) − 0.6·z(monthly_income_rank) − 1.2·[satisfaction = 1]`, 0 미만은 0으로 자른 뒤 **평균이 0.7이 되도록 배율 조정** | 승진 정체·급여 낮음 → 면담(처우 논의) 효과 큼. 만족도 1(이미 마음을 굳힘) → 효과 거의 없음 |

- 두 시나리오의 **평균 효과를 같게** 맞춰, 차이가 "효과의 분포"에서만 오게 한다.
- 진짜 값은 검증 전용 파일 `data/truth_<A|B>.csv`에 저장한다: `emp_id`, `p_leave_no_talk = sigmoid(logit0)`, `p_leave_talk = sigmoid(logit1)`, `true_uplift = 둘의 차`. **모델 입력에 쓰지 않는다.**

### 5.5 가상 데이터의 한계 (화면과 README·보고서에 반드시 표기)

- 퇴사 규칙과 면담 효과를 우리가 직접 정했으므로, **모델이 잘 맞추는 것은 규칙을 다시 찾은 것**이다. 실제 회사 성능을 뜻하지 않는다.
- **시나리오 B에서 업리프트가 이기는 것은 그렇게 설계했기 때문**이다. 그래서 효과가 균일한 시나리오 A를 반드시 함께 보여 준다.
- 요인 중요도도 우리가 넣은 규칙을 반영할 뿐이다.
- 이 프로젝트가 보여 주는 것은 "예측 성능"이 아니라 **"점수 → 문턱 → 비용 결정"을 연결하는 방법과 "무엇을 예측할지" 정하는 판단**이다.
- 잡음 크기를 바꾸면 AUC가 달라진다. 하나의 값만 대표 결과로 주장하지 않는다.
- 진짜 개인별 효과(`truth`)는 실제 자료에서는 알 수 없다. 이 값을 쓰는 비교는 "가상 데이터라 가능한 검증"으로 표시한다.

## 6. 모델링과 평가

### 6.1 분할

- 전체 행에서 시험 자료 **30%** 를 한 번 떼어 끝까지 고정한다. 층화 기준은 `treated × left`, 시드 고정.
- 1단계는 훈련·시험 각각의 **대조군(`treated = 0`)만** 쓴다 → "면담하지 않았을 때의 위험"을 배운다.
- 2단계는 훈련·시험의 **전체 행**을 쓴다.
- 시험 정답은 채점에만 쓴다. 모델 선택·보정은 **훈련 자료 안의 교차 검증(5겹)** 으로 한다.

### 6.2 1단계: 위험 예측 (교안 17번 그대로)

| 구분 | 방법 | 역할 | 우선순위 |
|---|---|---|---|
| 기준선 1 | 무작위 순서 (시드 고정) | 아무것도 모를 때 | P0 |
| 기준선 2 | 근속 연수 짧은 순 | 사람이 쓰는 단순 규칙 | P0 |
| 기준선 3 | 로지스틱 회귀 | 단순 모델 | P0 |
| 모델 | 랜덤 포레스트 | 표 데이터 기본 모델 (교안) | P0 |
| 모델 | HistGradientBoosting | sklearn 내장 빠른 부스팅 | P0 |
| 모델 | GradientBoostingClassifier | 교안의 그래디언트 부스팅 | P1 |
| 제외 | TabICL·TabPFN·LightGBM | 일정상 제외 (INTERVIEW Q6) | — |

- 입력 열: §5.3의 "모델 입력 O" 열. 하이퍼파라미터는 기본값(시험 점수로 튜닝하지 않음).
- **확률 보정 (P0):** 모델 점수를 `CalibratedClassifierCV`(훈련 자료 5겹, isotonic)로 확률에 맞춘다. 보정 전후 Brier 점수와 신뢰도 곡선(10구간)을 저장한다.
- **1단계 대표 모델:** 훈련 자료 교차 검증 AUC가 가장 높은 모델. 2단계의 "위험 순" 기준선으로 넘긴다.

### 6.3 2단계: 업리프트 (교안 확장)

| 구분 | 방법 | 역할 | 우선순위 |
|---|---|---|---|
| 기준선 | 무작위 | 아무것도 모를 때 | P0 |
| 기준선 | **위험 순** (1단계 대표 모델의 보정 확률) | 교안 방식 그대로 쓰면 | P0 |
| 모델 | **T-learner**: 면담군·대조군에 HistGradientBoosting을 따로 학습, `uplift = p(대조) − p(면담)` | 면담 효과 추정 | P0 |
| 상한 | 진짜 효과 순 (`truth`) | 가상 데이터라서만 가능한 최선 | P0 |

- 시나리오 A·B 각각 같은 절차로 실행한다.

### 6.4 지표

| 지표 | 단계 | 뜻 |
|---|---|---|
| 정확도 (문턱 0.5) | 1 | 전체 시험 행 중 맞힌 비율 |
| 전원 재직 정확도 | 1 | "모두 남는다"고만 답할 때의 정확도. 정확도 함정을 보이는 기준 |
| ROC AUC | 1 | 퇴사자에게 재직자보다 높은 점수를 주는 정도 |
| Brier 점수 (보정 전/후) | 1 | 확률이 실제와 얼마나 가까운지 (낮을수록 좋음) |
| 포착률@k | 1 | 전체 퇴사자 중 상위 k%에 들어온 비율 (k = 5, 10, 20, 30%) |
| 리프트@k | 1 | 상위 k%의 퇴사자 비율 ÷ 전체 퇴사자 비율 |
| Qini 계수 | 2 | 효과 순으로 줄 세운 정도. 무작위 = 0, 클수록 좋음. 관측 자료(면담군·대조군 비교)로 계산 |
| 진짜 효과 상관 | 2 | 추정 효과와 `true_uplift`의 순위 상관(스피어만). **가상 데이터라 가능한 검증** |
| 순이익@k | 1·2 | §7 식, 웹에서 계산 |

### 6.5 설명·공정성 (P1)

- **순열 중요도:** 1단계 대표 모델과 T-learner에 대해 시험 자료에서 계산한다(보고용, 모델 선택에 쓰지 않음). "원인이 아니라 상관"으로 안내한다.
- **집단별 점검:** 나이대(30세 미만 / 30대 / 40대 / 50세 이상)·성별마다 k = 20%일 때의 선정 비율과 포착률을 위험 순과 효과 순 각각으로 계산한다.
- 민감 열 포함 모델 재학습(F8 전체판)은 제외한다(INTERVIEW Q6).

### 6.6 원칙

- 직접 실행한 값만 기록한다. 17번 원문 수치나 추정치로 채우지 않는다.
- 분할 시드, 패키지 버전, 실행 시간, 실제 퇴사 비율(대조군·면담군), 최종 생성 계수를 `results/meta.json`에 남긴다.
- 점수가 같으면 행 순서가 아닌 **고정 시드 무작위**로 깨고, 순위(rank)를 Python에서 계산해 `scores.json`에 저장한다. 웹은 그 순위만 쓴다.

## 7. 비용 계산 (웹에서 계산)

**입력**
- `C_replace`: 퇴사 1건당 대체 비용 (기본값 없이 입력)
- `C_talk`: 면담 1건당 비용
- `r`: (1단계만) 면담한 퇴사 위험자 중 퇴사를 막는 비율 0~1
- `k`: 면담 대상 비율(상위 k%), 1~100%
- "예시값 채우기" 버튼: `C_replace` 3,000만 원, `C_talk` 50만 원, `r` 0.3, `k` 20% — **예시임을 화면에 표시**

**1단계 (단순 가정, 성공률 `r`이 모두 같음)** — 시험 대조군 N명

- `S = round(N × k)`, `TP` = 선정된 실제 퇴사자 수
- 불필요한 면담 = `S − TP`
- 예상 순이익 = `TP × r × C_replace − S × C_talk`
- **기대이익 문턱 비교:** 보정 확률 `pᵢ`로 `pᵢ × r × C_replace > C_talk`인 사람만 고르는 방식의 순이익과 인원을 같은 화면에 표시한다.

**2단계 (사람마다 효과가 다름)** — 시험 전체 행

- 선정된 사람의 진짜 효과 합으로 계산: 예상 순이익 = `Σ(선정자의 true_uplift) × C_replace − S × C_talk`
- 위험 순·효과 순(T-learner)·무작위·진짜 효과 순(상한)을 같은 `k`로 비교한다.
- "진짜 효과는 가상 데이터라서 알 수 있는 값"이라고 표시한다.

문구: "가정에 따른 시뮬레이션이며 실제 이득을 보장하지 않습니다."

## 11. 윤리·보안 요구사항

- 점수는 면담·지원 대상 선정용이며 평가·징계·해고 근거로 쓰지 않는다고 화면·README·보고서에 명시한다.
- 개인 이름·ID를 표시하지 않는다. `scores.json`에는 행 번호만 둔다.
- 민감 열은 모델 입력에서 제외한다. 공정성 점검에서만 집계로 쓴다.
- 요인 설명은 상관으로 한정한다.
- 업리프트로 "효과가 없는 사람"을 고르는 것은 **지원을 끊는 근거가 아니라 예산 배분의 우선순위**임을 명시한다.
- 가상 데이터임과 그 한계(§5.5)를 첫 화면에 표시한다.
- 실제 직원 자료는 사내 규정 확인 없이 사용하지 않는다(17번 6파트).

## 16. 용어

| 용어 | 뜻 |
|---|---|
| 양성 | 찾아내려는 쪽. 여기서는 퇴사 |
| 기준선 | 새 방법의 이점을 판단하려고 함께 비교하는 기존 방법 |
| AUC | 퇴사자에게 재직자보다 높은 점수를 주는 정도(점수 순서의 구별 능력). 전체 행의 몇 %를 맞혔다는 뜻이 아님 |
| 문턱(`k`) | 점수 상위 몇 %부터 면담 대상으로 볼지 정하는 기준 |
| 포착률 | 전체 퇴사자 중 선정된 대상에 들어온 비율 |
| 리프트 | 선정 대상의 퇴사자 비율이 전체 평균의 몇 배인지 |
| 확률 보정 | 점수가 실제 확률과 맞도록 고치는 일. 0.3이라는 점수의 사람들 중 실제로 약 30%가 떠나게 맞춤 |
| Brier 점수 | 예측 확률과 실제 결과(0/1)의 차이 제곱 평균. 낮을수록 좋음 |
| 업리프트 | 면담했을 때와 안 했을 때의 퇴사 확률 차이. "면담 효과" |
| T-learner | 면담군과 대조군에 모델을 따로 학습해 두 예측의 차이로 효과를 추정하는 방법 |
| Qini 곡선·계수 | 효과 순으로 줄 세웠을 때 누적으로 막은 퇴사 수를 그린 곡선과 그 면적 요약. 무작위 = 0 |
| 대조군 / 면담군 | 시범 운영에서 면담하지 않은 사람 / 면담한 사람 (무작위 배정) |
