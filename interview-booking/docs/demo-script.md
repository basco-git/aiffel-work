# 3분 시연 대본

> **2026-11-04: 시연 영상은 상황별 캡처 8장으로 대체했어요** → [README의 시연 캡처](../README.md#시연-상황별-캡처). 아래 대본은 캡처 순서를 고를 때 기준으로 썼어요.

> 준비: 담당자 로그인 상태, 면접관 링크 2개, 후보자 링크 2개를 미리 브라우저 탭에 열어 두세요.
> 화면 녹화는 담당자 화면에서 시작해 링크 화면으로 넘어가며 찍으면 돼요.

## 0:00–0:20 — 무엇을 만들었나

**말할 것**
"면접 한 건을 잡으려면 면접관 2~3명과 후보자 시간을 다 맞춰야 해서, 메일이 여러 번 오갑니다. 이 서비스는 **면접관 일정이 모인 시간만 후보자에게 열어 주는** 예약 페이지예요."

보여 줄 것: 첫 화면(담당자 로그인 → 포지션 목록).

## 0:20–0:50 — 담당자: 시간 후보와 링크

1. 포지션 선택 (필요 면접관 2명)
2. 시간 후보 3개 추가 (예: 내일 10:00·11:00·14:00, 30분)
3. 면접관 2명 추가 → **링크 복사** 버튼
4. 후보자 2명 추가

**말할 것**
"면접관과 후보자는 로그인 없이 각자 링크로만 들어옵니다. 받는 정보는 이름뿐이에요."

## 0:50–1:30 — 면접관: 겹치는 시간만 열림

1. 면접관 1 링크 → 10:00, 11:00 체크
2. 면접관 2 링크 → 10:00만 체크
3. 담당자 화면으로 돌아오기 → 10:00만 "열림 2/2", 11:00은 "닫힘 1/2"
4. 후보자 링크 열기 → **10:00만 보임**

**말할 것**
"필요 인원이 모이지 않은 시간은 후보자 화면에 아예 나오지 않습니다. 화면에서 숨긴 게 아니라 서버가 주지 않아요."

## 1:30–2:10 — 후보자: 예약과 변경

1. 후보자 1 링크에서 10:00 예약
2. 담당자 화면 → 예약자 이름 표시, 포지션 목록과 상세에서 확정됨으로 보이고, 목록 상단에 확정된 면접 일정이 보임
3. 후보자 2 링크 → 10:00이 "마감"으로 보임
4. (여유가 있으면) 후보자 1이 다른 열린 시간으로 **변경**

**말할 것**
"같은 시간을 동시에 예약하면 한 명만 성공합니다. DB가 슬롯 행을 잠그고 확인하기 때문이에요. 이건 따로 시험 스크립트로 10건을 동시에 보내 확인했습니다."

## 2:10–2:40 — 규칙이 화면 밖에서도 지켜짐

1. 담당자 화면에서 이미 있는 10:00과 겹치는 10:15 추가 → **"이미 겹치는 시간 후보가 있어요"**
2. 예약된 시간을 면접관 링크에서 해제 시도 → **"이미 예약된 시간이라 해제할 수 없어요"**

**말할 것**
"버튼을 숨기는 게 아니라 DB 제약과 함수가 거부합니다. 링크를 복사해 직접 요청을 보내도 같아요."

## 2:40–3:00 — 마무리

**말할 것**
"하루 안에 끝내려고 캘린더 연동·메일 자동 발송은 일부러 뺐습니다. 대신 일정이 모인 시간만 열린다는 핵심 하나를 DB 규칙까지 확실히 했어요. 다음은 실제 배포 주소에서 다른 기기로 확인하고, 캘린더 연동을 붙이는 것입니다."

## 비상시 대체 멘트

- 예약이 이미 차 있으면: "다른 탭에서 먼저 예약된 상태입니다. 이렇게 마감으로 보이는 것이 정상 동작이에요."
- 네트워크 오류가 나면: "지금은 서버 연결이 끊겨 안내 문구가 뜬 상태입니다. 새로고침해 다시 보여 드릴게요."

## 상황별 캡처 다시 찍기 (README "시연" 10장)

화면이 바뀌면 아래 두 명령으로 `docs/screenshots/` 10장을 다시 만들어요. 한 번 실행에 약 70초 걸려요.

| 명령 | 하는 일 |
|---|---|
| `npm run capture -- login` | 캡처 전용 크롬 창 2개를 열어요. `#A` 창은 관리자 A, `#C` 창은 계정 C로 **직접** 로그인한 뒤 두 창을 닫으면, 로그인이 저장됐는지 확인해 알려 줘요. 한 번 해 두면 다음에도 유지돼요. |
| `npm run capture -- check` | 두 프로필의 로그인 상태만 확인해요. |
| `npm run capture` | `[시연]` 포지션 3개 만들기 → 10장 캡처(1280px, 헤드리스 크롬) → 시연 데이터 삭제 → 계정 C 상태 원래대로 |
| `npm run capture -- clean` | 남은 시연 데이터와 로그인 프로필(`.capture/`)을 지워요. |

- 비밀번호는 브라우저에 자동 입력하지 않아요. 로그인 프로필은 `.capture/`에만 있고 git에 올라가지 않아요(`.gitignore`).
- 캡처 직전에 화면에 이메일이 남아 있으면 그 장은 저장하지 않고 멈춰요. 중간에 실패해도 시연 데이터 삭제와 계정 C 복원은 항상 실행돼요.
- 찍은 뒤 `docs/screenshots/`를 열어 확인하고 커밋해요. 바뀐 화면이 없으면 파일도 바뀌지 않아요(같은 결과가 나와요).
