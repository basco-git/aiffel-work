# AGENTS.md — at~once | interview-booking

> 브랜드명 **at~once** · 서비스명 **interview-booking**

AI 코딩 도구가 이 폴더에서 일할 때 늘 따르는 규칙이에요. 무엇을 만들지는 `PRD.md`가 정답이에요.

## 기준 문서
- `PRD.md`: 한 문장, 핵심 흐름, Must·Won't, 규칙 R1~R8, 성공 조건, 검증 기록(9장)
- `docs/design.md`: 기술 선택과 그 이유(계획 단계에서 작성)
- PRD의 Won't 항목은 사람이 PRD를 고치기 전에는 만들지 않는다.

## 작업 방식
- 사용자에게 보이는 글, 커밋 메시지, 문서, 코드 주석은 한국어로 쓴다. 코드 식별자·명령어·오류 원문은 그대로 둔다.
- **한 번에 하나만** 바꾼다. 요청받지 않은 파일·기능은 건드리지 않는다.
- 코드를 쓰기 전에 무엇을 바꿀지 짧게 말하고, 파일 삭제·덮어쓰기·DB 구조 변경은 먼저 계획을 보여 주고 승인을 받는다.
- 규칙 R1~R8은 **화면이 아니라 데이터 저장 쪽(DB 제약·함수·권한)**에서 막는다. 버튼 숨기기는 통과가 아니다.
- 같은 문제를 두 번 고쳐도 안 되면 멈추고 "된 것 / 남은 것 / 지금 문제"를 요약해 사용자에게 보고한다.

## 커밋과 Git
- **작동을 확인했을 때만** 커밋한다. 메시지는 확인한 결과로 쓴다(예: "후보자 링크에서 열린 시간만 보임").
- 커밋 전: `git status` → 핵심 흐름 한 번 실행 → `git diff`로 비밀값·대량 삭제 확인.
- `git reset --hard`, 강제 푸시, 이력 수정은 사용자가 명시적으로 승인하기 전에는 실행하지 않는다. 공유한 변경은 `git revert`로 되돌린다.
- 작업은 `interview-booking` 브랜치에서 하고, main에는 PR로 합친다.

## 비밀값
- 비밀 키·DB 접속 문자열·토큰은 코드·문서·커밋·채팅에 넣지 않는다. `.env`에 두고 `.gitignore`에 등록한다.
- 브라우저 코드에는 공개 키만 넣는다. 관리자(service_role) 키는 테스트에도 쓰지 않는다(권한 검사를 우회하므로).
- 로그·오류를 보여 줄 때 비밀값과 개인 링크 토큰은 가린다.

## 검증
- 성공 조건과 R1~R8은 **실제 요청**으로 확인하고, 결과를 `PRD.md` 9장 표에 "결과 · 실제로 본 것 · 날짜"로 적는다. 안 되는 것은 지우지 말고 미완료로 둔다.
- 동시 예약(R1)은 테스트 스크립트로 같은 시간에 여러 요청을 보내 성공 건수를 로그로 보여 준다.
- 테스트 데이터만 지운다. 실제 데이터는 지우지 않는다.
- **`supabase/schema.sql`이나 권한 규칙(RLS·함수)을 바꾸면** `npm run test:rules`를 다시 돌리고, 바뀐 규칙에 맞게 시험과 `PRD.md` 5장·9장을 함께 고친 뒤 커밋한다. 옛 기준의 "통과" 기록을 남겨 두지 않는다.

## 사용량 아끼기
- 큰 파일은 통째로 읽지 말고 필요한 부분만 읽는다.
- 같은 내용을 다시 설명하지 않고, 보고는 짧게(바뀐 것 / 확인한 것 / 다음 할 일).
- 서브에이전트·여러 에이전트 작업은 사용자가 요청할 때만 쓴다.

## 진행 기록
- 커밋할 때마다 `docs/progress.md` 표에 한 줄(한 일 / 결정한 사람 / 확인한 것 / 커밋)을 남긴다.
- 대화를 이어받을 때는 `docs/handoff.md`부터 읽는다.
