# 면접 한 번에 — PRD

> 작성: 2026-11-03 · 상태: 확정 (Main Quest 01) · 제출 마감: 2026-11-04 오전

## 1. 한 문장

**내 전문 분야(HR)의 이 불편을**: 채용 담당 인사담당자가 면접 한 건을 잡으려면 면접관 2~3명과 후보자의 시간을 모두 맞춰야 해서 메일·메신저가 여러 번 오가고, 시간이 바뀌면 처음부터 다시 조율하며, 같은 시간에 두 후보자가 겹쳐 잡히기도 한다.

**서비스 한 문장**: 면접관들이 각자 링크로 가능한 시간을 표시하면, 면접관이 충분히 모인 시간만 후보자에게 열리고, 후보자가 링크로 직접 골라 예약하는 페이지.

## 2. 누가 쓰는가

| 사용자 | 하는 일 | 들어오는 방법 |
|---|---|---|
| 인사담당자 (핵심 사용자) | 회원가입·로그인한다. 계정마다 자기 포지션만 보인다 | 로그인 |
| 면접관 (면접 한 건에 2~3명) | 시간 후보 중 가능한 시간을 체크한다 | 로그인 없이 면접관마다 다른 링크로 |
| 후보자 | 열린 시간 중 하나를 예약하고, 필요하면 바꾼다 | 로그인 없이 후보자마다 다른 링크로 |

- 면접관·후보자에게 가입을 요구하면 응답이 늦어지고 개인정보가 늘어나므로, 첫 버전은 개인 링크로만 들어온다.
- 받는 정보는 **이름만**(연락처·이력서는 받지 않는다).

## 3. 핵심 흐름 하나

```
담당자 로그인 → 포지션 만들기(필요 면접관 수 2 또는 3) → 시간 후보 만들기(시작 시각 + 길이 15분 단위)
→ 면접관 링크 전달 → 면접관이 각자 가능한 시간 체크
→ 가능 면접관이 필요 인원 이상인 시간만 '열림'
→ 후보자 링크 전달 → 후보자가 열린 시간 중 하나 예약 → 그 시간은 '마감'
→ 담당자 화면에서 시간별 가능 면접관·예약자 확인
```

화면 구성은 10장, 데이터 구조는 11장에 정리했어요.

## 4. 범위 (MoSCoW)

**꼭(Must) 3개**
1. 담당자가 면접 시간 후보(시작 시각, 길이 15분 단위 15~120분, 기본 30분)를 만들고, 면접관은 각자 링크로 가능한 시간을 체크한다.
2. 가능 면접관이 필요 인원(2 또는 3명) 이상인 시간만 후보자에게 열리고, 후보자는 링크로 그중 하나를 예약한다.
3. 담당자가 시간별 가능 면접관과 예약자를 한 화면에서 본다.

**있으면 좋음(Should)** — Must가 끝나면 가장 먼저
- 후보자가 같은 링크로 예약을 다른 열린 시간으로 **변경**한다(기존 예약 해제와 새 예약을 한 번에 처리).
- 담당자가 예약을 취소한다.

**나중에(Could)**: 면접관이 예약 뒤 일정 변경을 요청하는 흐름, 포지션 여러 개 동시 관리, 예약 마감 시각.

**지금은 안 함(Won't)**
1. 구글·아웃룩 캘린더 연동(면접관 일정 자동 읽기)
2. 메일·문자 자동 발송 (링크는 담당자가 직접 전달)
3. 면접 평가표·합격 여부 관리
4. 화상면접 링크 자동 생성
5. 면접실(회의실) 예약
6. 다국어, 결제

## 5. 꼭 지켜야 할 규칙 (화면이 아니라 데이터 저장 쪽에서 막는다)

| # | 규칙 | 어기는 시도 → 기대 결과 |
|---|---|---|
| R1 | 한 시간에는 후보자 한 명만 | 두 후보자가 같은 시간을 **동시에** 예약 → 한 명만 성공 |
| R2 | 후보자 링크 하나로는 예약 하나만 | 같은 링크로 두 번째 시간 예약 → 거부 (변경은 R1을 지키며 한 번에) |
| R3 | 가능 면접관이 필요 인원 미만인 시간은 예약 불가 | 면접관 1명만 가능한 시간 예약 요청 → 거부 |
| R4 | 예약이 들어간 시간은 면접관이 '가능'을 해제할 수 없다 | 예약된 시간의 체크 해제 요청 → 거부, "담당자에게 문의" 안내 |
| R5 | 지난 시간은 예약 불가 | 지난 시간 예약 요청 → 거부 |
| R6 | 승인된 담당자만 실제 면접일정을 보고 함께 관리한다. 가입만으로는 접근할 수 없다 | 비승인·반려 계정과 비로그인으로 현황 조회·수정 → 거부 |
| R7 | 링크로는 자기 것만 | 면접관 링크로 다른 면접관 체크 변경, 후보자 링크로 다른 후보자·면접관 이름 조회 → 거부 (후보자는 열림·마감만 본다) |
| R8 | 비밀값은 코드와 저장소에 넣지 않는다 | 커밋·배포 파일에 비밀 키가 있는지 검사 |
| R9 | 같은 포지션의 시간 후보는 서로 겹치지 않는다 (면접관 이중 배정 방지), 길이는 15분 단위 | 14:00~14:30이 있는데 14:15~14:45 추가, 또는 길이 20분 → 거부 |

### 가입 승인과 포지션 공유

- 새로 가입한 계정은 승인 대기 상태로 들어가고, HR 일정 표를 볼 수 없어요.
- 관리자(계정 A)가 앱의 **회원 승인** 목록에서 승인하면 그 계정도 면접일정을 보고 만들고 수정할 수 있어요.
- 승인된 담당자끼리는 서로의 포지션·면접관·후보자·시간을 함께 보고 관리해요.
- 관리자는 **승인 취소**로 일반 회원의 앱 접근만 막을 수 있고, 기존 포지션·예약·후보자 데이터는 그대로 유지돼요.
- 포지션과 시간 후보의 **삭제**는 관리자만 가능하고, 면접관·후보자는 승인된 담당자가 앱에서 확인한 뒤 삭제할 수 있어요.
- 면접관·후보자는 계속 **링크만**으로 가능한 시간을 체크·예약해요. 회원 승인 권한과 무관합니다.

## 6. 완성 기준 (done)

배포 주소에서 담당자가 시간 후보 3개를 만들고, 면접관 2명이 링크로 체크해 2개가 열리고, 후보자 두 명이 각자 링크로 예약하면 담당자 화면에 반영되며, 같은 시간을 동시에 예약하면 한 명만 성공한다.

## 7. 최소 성공 조건 (직접 눌러서 확인)

1. 담당자로 로그인해 시간 후보를 추가하면 목록에 보이고, 새로고침해도 남는다.
2. 면접관 링크에서 체크한 결과에 따라, 필요 인원이 모인 시간만 후보자 링크에 '열림'으로 보인다.
3. 후보자가 열린 시간을 고르면 예약되고, 그 시간은 다른 후보자 링크에서 '마감'으로 보이며, 담당자 화면에 예약자 이름이 보인다.

## 8. 기술 선택

PRD에는 넣지 않는다. 계획 단계에서 AI가 후보를 비교해 고르고, 고른 이유와 트레이드오프를 `docs/design.md`에 남긴다.
조건: 무료로 시작할 것, 다른 기기에서 열리는 공개 주소로 배포할 것, 재배포 후에도 데이터가 남을 것, **2026-11-04 오전까지 만들 수 있을 것**.

## 10. 화면 구성

화면은 3개예요. 담당자만 로그인하고, 면접관·후보자는 각자 다른 링크로 들어와요.

| 화면 | 주소 | 누가 | 화면에 보이는 것 | 할 수 있는 일 |
|---|---|---|---|---|
| 담당자 | `/index.html` | 로그인한 담당자 | 포지션 선택, 면접관·후보자 명단과 개인 링크, 시간 후보별 가능 면접관 수와 예약자 | 회원가입·로그인, 포지션·면접관·후보자·시간 추가, 링크 복사, 예약 취소, 로그아웃 |
| 면접관 | `/interviewer.html?t=토큰` | 링크를 받은 면접관 (로그인 없음) | 포지션 이름, 내 이름, 시간 목록과 내 체크 상태 | 가능 체크·해제 (예약된 시간은 잠김) |
| 후보자 | `/candidate.html?t=토큰` | 링크를 받은 후보자 (로그인 없음) | 열린 시간과 예약한 시간. 면접관·다른 후보자 이름은 안 보임 | 예약, 다른 열린 시간으로 변경 |

- 화면 사이 이동은 링크 복사로 해요. 메일·문자 자동 발송은 Won't(4장)라서 담당자가 직접 전달해요.
- 시간은 모두 **한국 시간(KST)** 으로 표시하고, 입력도 한국 시간으로 해석해요.
- 휴대폰 폭에서도 한 줄로 읽히게 만들고, 오류는 서버 함수가 준 한국어 문장을 그대로 보여 줘요.

## 11. 데이터 구조

PostgreSQL(Supabase) 표 6개예요. 자세한 열·제약은 `supabase/schema.sql`, 설계 이유는 `docs/design.md`에 있어요.

| 표 | 주요 열 | 관계 | 맡는 규칙 |
|---|---|---|---|
| `positions` | id, owner_id, title, required_interviewers(2·3) | 담당자 1 : 포지션 N | R6 소유자만 |
| `interviewers` | id, position_id, name, token(고유) | 포지션 1 : 면접관 N | R7 링크=토큰, R7 이름은 자기 것만 |
| `candidates` | id, position_id, name, token(고유) | 포지션 1 : 후보자 N | R2 링크당 예약 1개 |
| `slots` | id, position_id, starts_at, duration_min(15~120, 15분 단위), ends_at(자동) | 포지션 1 : 시간 N | R9 겹침 금지·15분 단위 |
| `availability` | slot_id, interviewer_id (둘을 묶어 기본 키) | 시간 N : 면접관 M | R3 가능 인원 세기, R4 해제 금지 |
| `bookings` | slot_id(고유), candidate_id(고유), created_at, updated_at | 시간 1 : 예약 1 | R1 한 시간 한 명, R2 변경 |

```
positions ─┬─ interviewers ─┐
           ├─ candidates ───┼─ availability (시간×면접관)
           └─ slots ────────┴─ bookings (시간×후보자, 각각 고유)
```

- 링크 사용자(anon)는 표에 직접 접근할 수 없고, 토큰을 받는 함수 4개로만 자기 것을 읽고 써요. API는 `docs/api.md`에 정리했어요.
- 시험용 담당자 계정의 이메일·비밀번호는 `.env`에만 두고, 브라우저에는 공개 키만 넣어요(R8).
